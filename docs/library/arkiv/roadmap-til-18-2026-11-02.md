# Roadmap til kl. 18 — forside og plugin

**Skrevet:** 2. november 2026, 09:30 CET · **Mål:** forsiden færdig og pluginnet så langt som det kan komme uden
ejerens nøgler · **Frist:** 18:00 CET · **Arbejdssted:** cloud-sandkassen, repoet `steamgears-site`

Planen er bundet til det, der faktisk kan verificeres herfra. Den vigtigste begrænsning står først, fordi den
former hele forside-sporet.

---

## 0. Hvad der er blokeret, og hvad det betyder for planen

| Blokering | Konsekvens for dagen |
| --- | --- |
| **Sitet svarer 401 på skrivning** (`POST /wp-json/wp/v2/posts`, MCP uden `MCP_ACCESS_TOKEN`) | Forsiden kan **ikke** publiceres herfra. "Færdig" betyder derfor: færdig som repo-leverance — markup, beslutning og verifikation — klar til indsættelse med to klik |
| **Ingen browser** | Ingen Lighthouse, ingen visuel kontrol. Tjek sker som HTTP + markup |

| **P1.5 kræver Pinterest-token og Meta-review** | Uden for scope; tæller ikke som fremgang |
| **P2.1–P2.4 kræver tokens/beslutning** | Uden for scope |

**Ærlig afgrænsning:** pluginnet er 23 developer-dage fra færdigt. Kl. 18 kan det ikke være "færdigt" i den
betydning. Målet er i stedet **set-and-forget-grundlaget**: P0 så langt som muligt, P1.1 og P1.3 bygget og
testet, P3.1/P3.5 ryddet. Alt andet rapporteres som rest, ikke som nået.

## 1. Definition på "færdig" kl. 18

### Forsiden (5 punkter, alle verificerbare)

1. **H1/titel-beslutningen er taget** (S2.4) og skrevet ned med begrundelse — shop-ramme eller workshop-ramme,
   ikke begge.
2. **Et homepage-blok ligger i repoet** (`css/home-*.html`) med hero, primær CTA og tillidssektion, der kun
   bruger klasser og strukturer temaet allerede har.
3. **Hvert link i blokken svarer 200** — målt med `curl`, ikke antaget.
4. **Header og footer er gennemgået** for forældede links og den samme 200-regel (de ligger allerede i `css/`
   som de live template parts).
5. **En indsætnings- og verifikationsnote** findes, så ejeren kan gøre det færdigt i wp-admin på under fem
   minutter, inkl. W3TC-purge.

### Pluginnet

1. **P0 fra 3,2/4,0 til 3,5/4,0** (P0.4 cron-honesty færdig; P0.6 forbliver blokeret og står som 0).
2. **P1.1 pre-flight-validering bygget** med tests pr. kanal.
3. **P1.3 blackout-kalender bygget** med tests.
4. **P3.1 oprydning:** død metode væk, de ubrugte indstillinger fjernet eller koblet på — med begrundelse pr.
   indstilling, ikke en massefjernelse.
5. **P3.5 verifikation:** `uninstall.php` rydder også de tabeller og indstillinger, der er kommet til siden
   (auditloggen er ny).
6. **Zip, version, roadmap, tests og status opdateret** i samme commit som ændringen.

**Ikke i scope i dag:** P0.6, P1.2, P1.4, P1.5, P1.6, P2.x, P3.2, P3.4.

## 3. Rækkefølge og hvorfor

1. **Forsiden før pluginnet.** Forside-arbejdet ender i en leverance, der kræver ejerens hånd (indsæt + purge).
   Jo før den ligger klar, jo større er chancen for at den bliver lagt ind i dag.
2. **Beslutningen før markuppen.** S2.4 er et enten-eller, og alt andet arbejde på forsiden arver svaret. At
   bygge hero-markup først ville betyde to gange arbejde.
3. **P1.1 før P1.3.** Pre-flight er den ændring, der fjerner flest uforklarlige fejl (det var hele pointen med
   P0.5-loggen), og den har en ren testflade uden datoer.
4. **P0.4 før P3.1.** Cron-honesty er reel funktion; oprydning er hygiejne. Buffer går til det første.
